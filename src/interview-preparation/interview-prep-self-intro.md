# 自我介绍怎么说才不像背书？

> 自我介绍不是把简历念一遍，是给面试官递几个能追问的钩子。

## 自我介绍到底在解决什么问题

很多人把自我介绍理解成"汇报履历"——我是谁、哪毕业、会什么、做过什么项目，照着简历顺着念。但换到面试官的位置想一想：他大概五分钟前才拿到你的简历，还没细看，接下来要用三十到四十分钟判断你能不能胜任这个岗位。自我介绍对他来说是个"热身"，他需要一张能快速定位你的地图，更需要一些**能接着往下问的由头**。

所以自我介绍有三个任务，按重要性排：

| 任务         | 在解决什么                                           | 为什么重要                                   |
| ------------ | ---------------------------------------------------- | -------------------------------------------- |
| 建立第一印象 | 开头三十秒定调：你表达是否清楚、有没有结构、紧不紧张 | 第一印象有锚定效应，后面答得再好也难完全翻盘 |
| 引导追问方向 | 把话题往你准备最透的地方引                           | 这条最被低估，下面单独讲                     |
| 控节奏       | 让你主导议程，而不是被动接面试官的随机提问           | 不埋钩子，面试官就回自己的题库，你被带着走   |

第三条最容易被忽略。如果你自我介绍里啥都没埋，面试官只能回他兜里的标准题——"讲讲 HashMap 原理""TCP 三次握手"——你完全没法预测会被抽到哪一题。但如果你开口就说"我最近在搞限流，踩过令牌桶的坑"，接下来那句大概率变成"那你那个限流怎么做的"，于是整场都围着你提前准备好的东西展开。**自我介绍本质是你在替面试官出题。**

> 纠偏：不少资料把自我介绍的目标笼统说成"用简洁的语言突出亮点、推销自己"。方向没错，但"推销自己"容易让人堆形容词——"我很努力、我很热爱编程、我学习能力强"——这恰恰是背书感的来源。真正的亮点不是形容词，是带具体数字和取舍的技术动作。

## 三段式：现在做什么 / 过往亮点 / 为什么来这个岗位

不用纠结先讲哪句，用一个稳定的三段式就行：

| 段            | 讲什么                                    | 占比     | 这段的任务                   |
| ------------- | ----------------------------------------- | -------- | ---------------------------- |
| 第一段 现在   | 你现在的角色、技术栈、在做什么            | 20–30 秒 | 让对方快速定位你"是哪一类人" |
| 第二段 亮点   | 1–2 个最有含金量的项目，每个带数字 + 取舍 | 60–90 秒 | 递钩子，把追问往这引         |
| 第三段 为什么 | 为什么投这个岗位，简单收束                | 15–20 秒 | 表达匹配度，不灌水           |

第二段是主战场，前面和后面都是给它服务的。给你一个社招技术面的范例（按正常语速约两分钟）：

> 面试官您好，我叫 XXX。现在在一家做电商的公司做 Java 后端，主要负责订单和支付链路，技术栈是 Spring Cloud + MySQL + Redis + RocketMQ。
>
> 我挑两个做得比较深的讲。一个是订单库的分库分表改造：原来订单表单表涨到 8000 万行，大促时写入和查询都在抖，我主导按用户 ID 做了分库分表，拆成 16 个分片，写入 TPS 从单库的 1500 提到整体的 4000，查询只要走分片键基本都能命中单分片。选 16 而不是 8，是因为预估未来两年数据量还要翻倍，提前留扩容余量。
>
> 另一个是支付回调链路的一次故障止血：凌晨下游银行接口变慢，我们原来的固定重试 3 次触发了重试风暴，反而把下游打得更慢。我先调大超时、暂停自动重试止血，复盘后加上了指数退避加熔断，这类故障的平均恢复时间从 25 分钟压到 6 分钟以内。
>
> 投贵公司，是因为你们在支付方向的技术挑战和我现在做的这块最对口，我想在更高并发量的环境里把这些东西做得更深。

注意几个点：开头一句就交代清楚"做什么的"，不绕；两个项目每个都带数字（8000 万、1500→4000、25→6 分钟），也都带取舍（选 16 不选 8、退避 + 熔断而不是重试到底）——这些数字和取舍就是钩子。结尾点到"支付方向最对口"就收，不堆"期待与您共事"。

> 一个反直觉的点：技术面的甜点区其实是 1.5–2 分钟，不是越长越好。超过两分钟面试官就开始想打断你。而且**被早打断是好事**——你讲到第一个钩子（"拆成 16 个分片"）就被一句"等一下，分片键你怎么选的"截住，恭喜，你的钩子生效了，接下来整场很可能就围着你准备好的东西展开。准备两三分钟的稿子，但内心期待着在第一分钟就被打断。

### HR 面和技术面要各备一版

这一点资料里讲对了，值得强调：同一份自我介绍准备两个版本，钩子埋在不同方向。

- **技术面版**：讲技术细节、项目里的取舍和数字（上面那个范例）。技术官会追着分片键、退避公式往下问。
- **HR 面版**：讲经历、成长、稳定性、为什么离职、怎么看团队协作，技术一语带过。HR 不会追问分片键，但会追问"为什么离开上家""职业规划三年怎么走"，所以 HR 版的钩子要埋在这些软问题上。

别混着用——给 HR 讲分片键她听不进去场面尴尬，给技术官讲"我热爱编程、积极乐观"他翻白眼。

## 埋钩子：让面试官主动往你准备好的方向问

这是把"背书"和"不背书"分开的关键技术。

背书感的本质，是每句话都是平的"我做了 X"——面试官听完抓不到点，只能回自己的题库。钩子的本质，是每句话都是"我做了 X，因为 Y"或"我做了 X，导致 Z"，那个 Y 和 Z 就是追问的入口；而因为是你自己埋的，你百分之百准备过答案。

| 你埋的钩子                  | 面试官大概率追问                   | 你要提前备好                      |
| --------------------------- | ---------------------------------- | --------------------------------- |
| "选 16 个分片而不是 8 个"   | 为什么是 16？以后扩容怎么办？      | 分片键选择、一致性 hash、成倍扩容 |
| "加了指数退避和熔断"        | 退避公式怎么定？熔断阈值呢？       | 退避算法、Sentinel/Hystrix 原理   |
| "业余维护了个开源 RPC 框架" | 为什么不用 Dubbo？服务发现怎么做？ | 注册中心、负载均衡、序列化        |
| "缓存命中率提到 96%"        | 剩下 4% 怎么处理？雪崩怎么防？     | 布隆过滤、随机 TTL、多级缓存      |

埋钩子有两条铁律：

**第一，埋 2–3 个就够，不要埋 5 个。** 埋太多面试官记不住，而且你每个都得备答案，准备不过来；一旦被问到答不上，反而从"递钩子"变成"给自己挖坑"。

**第二，钩子必须是你真准备透的。** 你说"我做过 JVM 调优"，但如果实际只会调个堆大小，面试官一问 GC 日志分析就露馅。埋钩子的目的是把自己往主场引，前提是这块原理你提前啃过——这和准备项目是一个道理，简历上写的技术点都要吃透，自我介绍里埋的钩子更要吃透，因为它一定会被追到。

## 差的自我介绍 vs 好的自我介绍

把上面几条拧成一张对比表，准备时对着自查：

| 维度   | 差的（背书感）                                           | 好的（带钩子）                                                             |
| ------ | -------------------------------------------------------- | -------------------------------------------------------------------------- |
| 开头   | "我叫 XX，毕业于 XX 大学 XX 专业……"                      | "我叫 XX，现在做 Java 后端，主要负责订单链路"                              |
| 技术栈 | "熟练掌握 Java、Spring、MySQL、Redis、Kafka……"（报菜名） | 只点 2–3 个和岗位最相关的，每个后面跟一句使用场景                          |
| 项目   | "参与了一个分布式系统的开发，负责搭建架构"               | "主导把订单表分库分表，单表 8000 万行拆 16 分片，写入 TPS 从 1500 到 4000" |
| 兴趣   | "业余喜欢打球、看技术博客"（和岗位无关）                 | 略；或换成"业余维护个开源 RPC 框架，2k star"（本身是钩子）                 |
| 结尾   | "我一直非常想加入贵公司，期待与您共事！"                 | "投这个岗位是因为你们支付方向和我做的最对口"（具体到岗位）                 |
| 时长   | 念简历三分钟还没说完                                     | 一分半到两分钟，留钩子等人打断                                             |

> 纠偏：有的资料给的自我介绍范例，结尾是"我一直都非常想加入贵公司，期待能与你共事"，中间还插"生活中我比较积极乐观，一般通过打球放松"。这种话术本身就是背书感的来源——面试官一天听十几遍一模一样的收尾，完全留不下印象，还挤掉了本该留给钩子的时间。技术面里兴趣爱好这块，除非它能变成钩子（开源项目、技术博客有真实产出），否则一句带过甚至不讲更好。

## 容易踩的坑

- **背书感**：通篇"熟练掌握、深入了解、熟悉"，全是程度副词没有事实，面试官抓不到点。
- **流水账**：把简历上的项目按时间顺序每个报一遍，每个都没展开，等于在念简历。
- **与岗位无关**：报一堆岗位用不到的技术，或者花时间讲和岗位方向无关的项目。
- **时长失控**：太长（三分钟没说完，面试官已经在想怎么打断你）；太短（三十秒"我叫 XX 做 Java 的"就结束，没递钩子，直接进入随机提问）。
- **钩子埋自己没准备的**：为了显得厉害埋"我做过 JVM 调优"，一问就露馅，从递钩子变成挖坑。
- **HR 面和技术面用同一版**：给 HR 讲分片键、给技术官讲"我热爱编程"。
- **数字编太圆**："性能提升 3 倍"却答不上怎么测的，不如给个区间并诚实说明是估算的。

## 小结

1. 自我介绍有三个任务：建第一印象、引导追问、控节奏，不是汇报履历。
2. 三段式：现在做什么 / 过往亮点 / 为什么来，亮点段占大头并埋钩子。
3. 钩子就是带"因为 Y"的技术点，埋 2–3 个你最透的就够，且必须真准备过。
4. 技术面和 HR 面各备一版，钩子埋在不同方向。
5. 一分半到两分钟是甜点区，被早打断是好事——说明钩子生效了。
