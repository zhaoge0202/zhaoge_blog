# 数据开发岗怎么准备面试？从 JD 拆解到项目叙述怎么走？

> 数仓岗的面试有个特点：技术广度问得浅，项目深挖问得狠。所以准备的重点不是多背十个概念，而是把**你做过的那两件事讲到能扛住五层追问**。

## 第一步：把 JD 逐条翻成考点

招聘要求写的是"职责"，面试官问的是"具体怎么做"。翻译一遍，你就知道该准备什么：

| JD 里的说法                           | 考官真正会问的                                         | 你要准备的答案                                   |
| ------------------------------------- | ------------------------------------------------------ | ------------------------------------------------ |
| 离线与实时数据管道的开发与运维        | 调度依赖怎么配？任务挂了怎么定位？重跑会不会重复出数？ | 分区覆盖写、业务日期参数、补数脚本、SLA 与告警   |
| 数仓分层（ODS/DWD/DWS/ADS）设计与优化 | 为什么这么分层？DWD 的粒度怎么定的？                   | 分层职责与依赖方向、粒度即复用上限               |
| 维度建模、事实表设计                  | 星型还是雪花？事实表有几种？维度变了怎么办？           | 事实表三类型、一致性维度、SCD 与拉链表           |
| 指标口径梳理、报表与看板              | 同一个指标两个部门不一致怎么办？                       | 指标字典、原子/派生指标、变更流程                |
| 数据质量监控体系、校验规则            | 你会配哪些校验？发现异常怎么查？                       | 六维校验、波动阈值、排查四步法                   |
| SQL 调优、任务链路优化、资源成本      | 一个任务跑 6 小时你怎么优化？                          | 倾斜解法、小文件治理、参数与成本，带前后对比数字 |
| 数据服务 API 协作                     | ADS 表怎么对外提供？为什么不让 BI 直查明细？           | 宽表预聚合 + 查询服务 + 缓存限流                 |
| 对接集团数据平台、数据申请入湖        | 你们的数据资产怎么登记？入湖流程走过吗？               | 资产登记、审批流、血缘，讲你实际参与的角色       |

一个提醒：**"参与"和"负责"要分清**。JD 里这些条目你不可能每条都是主 R，面试时如实说边界（"分层规范是团队定的，我负责交易域的 DWD 落地"），比全都揽到自己身上安全得多。

## 第二步：项目用五段式讲，每段都要有数字

准备两个项目，每个都按这个骨架写成稿子，念到 3 分钟以内：

```text
① 业务背景：什么业务、多大数据量（日增 X 万订单 / X TB 日志 / X 张表）
② 我的边界：我负责哪几层、哪几个主题域，哪些是同事做的
③ 技术方案：链路怎么走、用什么引擎、分层怎么落、调度怎么配
④ 一个具体难点：现象 → 原因 → 我怎么解的 → 怎么验证没解坏
⑤ 量化结果：耗时 X → Y、成本降 Z%、支撑 N 个下游/看板
```

第四段是全场最值钱的部分。可选素材（挑一个你真遇到过的）：

- 某个商户/主播的数据占了 40%，reduce 卡在 99% —— 倾斜，怎么打散、怎么验证数据没变；
- 上游重复推送导致指标翻倍 —— 幂等去重，按业务主键 + `update_time` 取最新；
- 口径变更，两个报表差 8 个点 —— 找差异五维（源表/时间字段/过滤/去重/单位）；
- 历史数据回溯，补 90 天要跑 90 次 —— 并发控制 + 影子分区切换。

**数字要讲得可信**：面试官一定会问"6 小时这个基线是怎么来的"。所以你要能补一句"上线前的调度历史里有连续两周的耗时记录，取的是 P50"。凭空想一个数字又不解释来源，被追一句就露。

## 第三步：自我介绍的三分钟骨架

```text
我是 XX，目前在 XX 公司做数据开发，X 年经验，主要负责交易域的离线数仓。
（一句话代表项目）最近一年主导了订单明细链路的建设，把核心指标的产出时间从早上 9 点提前到 6 点半。
（技术栈与深度）技术上主力是 Hive + Spark SQL，实时用 Flink 做过 XX 分钟级的指标；建模上按 ODS/DWD/DWS/ADS 分层落，交易域有 XX 张表由我维护。
（为什么看机会）现在团队的数据量增长很快，但实时链路和治理体系还比较薄，我想找一个数据规模和工程规范都更成熟的团队继续深入。
```

三分钟里**不要背技术细节**，细节留给后面的追问。自我介绍的作用只有两个：给面试官一个提问的钩子，以及证明你说话有条理。

## 第四步：八股按三档分配时间

| 档位                | 内容                                                                                                               | 标准                                          |
| ------------------- | ------------------------------------------------------------------------------------------------------------------ | --------------------------------------------- |
| 必背（占 60% 时间） | 分层与职责、事实表三类型、粒度、SCD 与拉链表、SQL 手撕、数据倾斜、小文件、分区裁剪、幂等与重跑                     | 每个点能脱稿讲 3~5 分钟，并能接住"那如果……呢" |
| 加分（占 30%）      | Flink checkpoint 与端到端 exactly-once、watermark 与迟到数据、维表 join 三种做法、湖仓（Iceberg/Hudi）解决什么问题 | 能讲清机制和取舍，不必背参数细节              |
| 了解（占 10%）      | ClickHouse/Doris/HBase 各自适合什么、调度系统选型、数据服务的限流与缓存                                            | 一句话说清适用场景即可，别主动展开            |

判断标准很实用：**你能讲几分钟，就报几分**。简历上写"熟悉 Flink"，面试官就会问到 checkpoint 和状态；写"了解"，他就不会追。技术栈报得越宽，被问穿的概率越高。

### 追问树：面试官会顺着哪条线往下挖

数仓岗的追问路径其实很固定，提前走一遍，你就不会在第三层被问住。

```text
你说做过数仓分层
├─ DWD 的粒度怎么定的？ → 为什么不定在订单头？ → 那商品维度怎么分析？
│   └─ 维度表属性变了怎么办？ → 拉链表怎么合并？ → 补数时链会不会断？
你说任务跑得慢，优化过
├─ 慢在哪一步？ → 怎么判断是倾斜不是数据量？ → 倾斜怎么解？
│   └─ 打散之后口径变了吗？ → 怎么验证没改坏数据？
你说保证数据准确
├─ 幂等怎么做的？ → 重跑一次会翻倍吗？ → 上游重复推送怎么处理？
│   └─ 怎么发现重复的？ → 有校验规则吗？规则怎么配？
你说做过实时
├─ checkpoint 间隔多少？ → 端到端 exactly-once 靠什么成立？
│   └─ 迟到数据怎么办？ → 实时和离线对账怎么对？
```

每一层的答法都在本专题对应篇章里：粒度与维度看[维度建模](./dw-dimensional-modeling.html)，拉链看[缓慢变化维](./dw-scd-zip-table.html)，倾斜看[调优篇](./dw-skew-and-tuning.html)，幂等与对账看[离线管道](./dw-offline-pipeline.html)，实时看[实时链路](./dw-realtime-pipeline.html)。

准备方法很土但有效：**把这棵树画在纸上，自己对着每一层口述 30 秒**，卡在第几层就补哪一篇。

## 第五步：手撕 SQL 的训练法

- 每天 2 题，限时 8 分钟，**手写**（纸或纯文本编辑器，不开补全）；
- 按题型归类，一个骨架记一类：连续 N 天、Top-N、留存、同比环比、行转列/列转行、累计求和、漏斗、去重取最新、日期补齐；
- 建一个错题本，只记"我当时卡在哪一步"（是不知道用窗口，还是排序方向写反），不抄答案；
- 面试前一天把十二类骨架默写一遍，比刷三十道新题有用。

题型与完整写法见[手撕 SQL 那篇](./dw-sql-patterns.html)。

## 第六步：反问环节准备六个问题

反问是信息收集，也是最后一次展示专业度。挑 2~3 个问：

- 团队现在离线 / 实时的占比大概多少？实时主要是 Flink 吗？
- 指标是走统一指标平台，还是各业务线自己维护？
- 数据质量问题现在是阻断下游，还是事后告警？
- 这个岗位未来半年最重要的一个目标是什么？
- 数据量级和成本压力大概是什么水平？有资源紧张的时候怎么排优先级？
- 值班和 SLA 机制是怎样的？夜里出问题怎么升级？

不问薪资、不问加班、不问"我表现怎么样"。前两个留给 HR 环节，最后一个问出来会显得不自信。

## 第七步：四周节奏

| 周      | 主题       | 每天动作                                                                                                                                                       | 周末自测                                       |
| ------- | ---------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------- |
| 第 1 周 | 项目稿     | 写 2 个项目的五段式稿，各念 3 遍并录音                                                                                                                         | 对着录音挑毛病：哪句是空话、哪个数字讲不清来源 |
| 第 2 周 | 建模与指标 | 读[分层](./dw-overview.html)、[维度建模](./dw-dimensional-modeling.html)、[拉链表](./dw-scd-zip-table.html)、[指标体系](./dw-metric-system.html)，每天复述一节 | 白纸画出电商数仓分层图 + 五张核心表的粒度      |
| 第 3 周 | 管道与调优 | 读[离线管道](./dw-offline-pipeline.html)、[实时链路](./dw-realtime-pipeline.html)、[倾斜调优](./dw-skew-and-tuning.html)，每天 2 道手撕题                      | 口述"任务没出数怎么查""6 小时怎么优化"各一遍   |
| 第 4 周 | 模拟       | 读[数据质量](./dw-data-quality.html) + 手撕题型默写；找人做一次 45 分钟模拟面                                                                                  | 全程录音，复盘卡壳点，24 小时内补齐            |

通用求职技巧（简历怎么写、STAR 怎么套、紧张怎么处理）不在本篇重复，看面试准备专题的[四周计划](/interview-preparation/interview-prep-four-week-plan.html)、[项目叙述](/interview-preparation/interview-prep-project-star.html)和[反问清单](/interview-preparation/interview-prep-questions-to-ask.html)。

## 容易踩的坑

- **技术栈报得太宽**：简历写满 Hive、Spark、Flink、ClickHouse、Doris，结果是每个都被问一句然后每个都答不深。宁少写三个，把写的三个讲透。
- **把跑批说成实时**：说"我们的指标是实时的"然后被追问 checkpoint 间隔、迟到数据怎么处理，立刻露馅。
- **优化只说"调了参数"**：没有前后耗时、没有对账方式，等于没优化。
- **只讲工具不讲口径**：能说出用了哪些组件，说不出"这个数为谁服务、口径怎么定的"，会被判定为只做过执行层。
- **把团队成果说成个人成果**：面试官一旦追问细节（"这个分层方案是你提的吗？当时反对意见是什么？"）就会崩。
- **离职原因谈钱和人际**：只说成长和业务复杂度，哪怕真实原因就是钱。

## 面试后的动作

每场面完，24 小时内做三件事：把被问住的题写下来并补上正确答案；把面试官追问最多的那个方向标记出来（说明你的叙述在那块不扎实）；更新项目稿里被质疑过的数字来源。三轮面试下来，你的题库会比任何资料都贴合这个岗位。

## 小结

- 准备的第一步不是背八股，而是**把 JD 逐条翻译成"考官会怎么问"**，再倒推要准备什么。
- 项目按"背景 → 我的边界 → 方案 → 一个难点 → 量化结果"讲，难点要能说清现象、原因、解法、验证四个环节。
- 八股按必背/加分/了解分三档，用"能讲几分钟"作为掌握程度的唯一标尺，技术栈别报得比实力宽。
- 手撕 SQL 靠限时手写 + 题型归类 + 错题本，不是靠刷题量。
- 反问是最后一次展示专业度的机会；面试后 24 小时内补齐被问住的题，比多面一场更有价值。
