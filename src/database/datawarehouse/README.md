# 数据仓库

## 为什么重要

数据开发岗的面试看起来在问技术栈，实际上问的是**同一件事的四张面孔**：这张表为什么这么分、这个指标为什么这么算、这条链路为什么不能停、这次数字不对你是怎么查出来的。

和 MySQL 那种"有确定正确答案"的专题不同，这一块几乎没有标准答案，全是取舍：分层分几层、粒度定多细、实时值不值得做、口径变更要不要双跑。所以这里不堆术语，而是把每个取舍的**代价**讲清楚——面试官真正想听的也是代价，不是定义。

## 知识主线

分层与建模（含生态组件）→ 维度与指标 → 离线管道 → 实时链路 → 湖仓 → 性能与质量 → 业务对接与面试

## 怎么读这个专题

前四篇是"数仓长什么样"：先搞清 ODS/DWD/DWS/ADS 各管什么，再落到事实表和维度表怎么设计、维度变化怎么留历史、指标怎么定义才不打架。这四篇决定你能不能把一个数仓"讲出来"。

中间四篇是"数仓怎么运转"：离线调度、幂等重跑、实时准确性、倾斜调优、质量监控。这部分是工作年限的分水岭——同样一句"我负责数仓开发"，能不能接着讲出"任务挂了怎么办、数不对怎么查"，差别就在这四篇。

最后两篇是"怎么把它换成 offer"：手撕 SQL 的题型套路，以及 JD 拆解、项目叙述和四周节奏。前八篇是内容，这两篇是把内容组织成答案的方式。

## 面试焦点

被追问的从来不是"什么是数据仓库"，而是这几句：

- 你为什么这么分层？DWD 的粒度为什么定在这里？
- 这个指标的数为什么和另一个部门的对不上？你怎么处理的？
- 一张维度表属性变了，历史事实按哪个算？
- 任务昨天没出数，你怎么排查？跑到 6 小时你怎么优化？
- 实时链路你怎么保证不丢不重？和离线对得上吗？

这五个问题答得住，这个岗位的技术面基本就走到聊业务和聊意愿了。

## 前置知识

SQL 基本功（窗口函数、聚合、多表连接）、至少一种大数据引擎的使用经验（Hive / Spark SQL / Flink）。SQL 语法层面的内容不在本专题重复，看 [SQL 专题](/database/sql/)；索引、事务这些 OLTP 内部机制看 [MySQL 专题](/database/mysql/)。

## 目标人群

- 有 1~3 年数据开发经验，准备换到数仓 / 数据平台岗位的同学；
- 后端转数据开发，SQL 会写但对分层建模没有体系认知的同学；
- 需要向业务方解释"这个数为什么这么算"的 BI / 数据分析同学。

## 子模块

### 1. 分层与建模

- 为什么分层，四层各管什么
- 生态组件：HDFS/YARN/Hive/HBase、列存与分区
- 维度建模：事实表三类、维度表、一致性维度
- 缓慢变化维与拉链表
- 指标体系与口径治理

### 2. 管道与实时链路

- 离线管道：调度依赖、幂等、补数、SLA
- 实时链路：checkpoint、端到端 exactly-once、watermark、维表 join
- 湖仓：表格式、Catalog、快照与 compaction

### 3. 性能与质量

- 数据倾斜、小文件、参数与成本治理
- 质量六维、规则配置、异常排查、数据标准

### 4. 业务对接与面试

- Java 业务系统对接：埋点、CDC、指标回流
- 数仓场景的手撕 SQL 题型
- JD 拆解、项目叙述、四周节奏
