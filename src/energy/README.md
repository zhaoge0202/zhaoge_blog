# 数字能源

## 为什么重要

光伏和储能的业务系统，难点不在"把数据画到屏幕上"，而在四件互相咬合的事：

1. **数据从哪来**：站端设备说的是 Modbus、DL/T 645、IEC 104、IEC 61850，点表错一位，后面全是别人的数据；
2. **数据算成什么**：发电量有四种口径，分母有直流侧和交流侧，口径一变，PR 和大屏数字全变；
3. **数据怎么反过来控设备**：储能 EMS 要按电价、需量、并网约束决定充放电，控错了要么罚款要么伤电池；
4. **数据怎么变成钱**：结算要和电网、财务、厂商三方对账，差一个 15 分钟冻结点就要人工查一天。

这一栏按"建模 → 接数 → 算指标 → 做策略 → 管告警 → 出结算"的顺序组织，讲的是这个行业里**真的会出事的地方**，不是名词解释。

## 知识主线

```text
领域建模（站点/设备/点位/台账）
  → 站端规约与四遥（Modbus / 645 / 104 / 61850 + 电力监控安全分区）
  → 指标口径（发电量、等效小时、PR、SOC/SOH、需量、收益）
  → 控制策略（峰谷套利、需量控制、防逆流、有功/无功调节）
  → 告警与工单（分级、抑制、闭环）
  → 数据链路（聚合、补数、对账、结算）
```

## 和工业物联网专题的分工

[工业物联网](/iot/) 讲的是**下位机那一侧**：怎么读写寄存器、怎么组帧、断网丢包怎么兜、数据存时序库还是 MySQL。这一栏讲的是**电站与业务那一侧**：这些数据属于哪个设备、算成什么指标、怎么驱动策略和结算。两栏连起来读，才是一条完整的"从寄存器到结算单"的链路。

## 怎么用这一栏

1. 面试前先能画一棵电站对象树，并说清台账、点表、时序三者谁是谁的依据。
2. 指标篇的公式要能手算一遍，尤其是 PR 与 RTE 的分界点——被追问"你的数为什么和结算单不一样"时，答案就在这里。
3. 策略篇不要只背"峰谷套利"，要能说出控制闭环、约束条件和失败兜底，这才是做过 EMS 的人和看过文章的人的区别。
