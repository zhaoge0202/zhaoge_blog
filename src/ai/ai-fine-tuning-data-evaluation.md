# SFT 和 LoRA 怎样准备数据，怎么验证训练有没有用？

> 先明确期望行为和独立测试，再准备有来源的监督数据，训练参数变少并不会自动降低数据与验收要求。

## 工单助手训练以后，究竟应该变好在哪里？

假设助手经常漏掉工单报告中的证据时间，团队希望它稳定输出状态、来源、时间与未确认事项。
一条合格样本可以展示怎样解释 T-1048 的 `WAITING_VENDOR`，同时说明还没有供应商反馈。
实时状态和后续升级权限仍由工具与业务服务决定。

训练前先固定当前模型、提示词和评测集，确认失败属于可以由示范改善的行为。
若缺少可合法使用的数据，或尚无可重复的基线，应先补这些条件。
方案选择见[Prompt、RAG 与微调](./ai-fine-tuning-decision.html)。

## SFT 和 LoRA 为什么可以一起使用？

SFT 用输入与期望输出训练模型，常见目标是降低目标 Token 的条件负对数似然。
全参数更新和参数高效适配都可以用于这个监督目标。
LoRA 冻结选定的原始权重，通过低秩矩阵学习增量，常写成 `W′ = W + BA`，实现中还可能带缩放系数。

若 W 的形状为 `d_out × d_in`，可令 B 为 `d_out × r`、A 为 `r × d_in`。
增量矩阵的参数数目为 `r(d_in + d_out)`，而原矩阵有 `d_in × d_out` 个参数。
实际训练还包含激活、优化器状态及其他可训练部分，不能只用这个比例预测显存或总成本。

| 名称  | 关注的层面                   | 需要另外确定的事项           |
| ----- | ---------------------------- | ---------------------------- |
| SFT   | 用哪些监督目标学习行为       | 数据、损失计算与参数更新范围 |
| LoRA  | 怎样表示选定权重的更新       | 秩、目标模块、缩放和训练配置 |
| QLoRA | 量化基座与低秩适配的组合路线 | 量化实现、数值格式和硬件支持 |

低秩适配与量化不能互相等同。
将增量合并进权重也不保证在所有部署形态下性能相同，需核对量化、精度和服务实现。

## 一条训练记录，除了正确答案还要保留什么？

下面是教学用的内部样本，工单和元数据均为合成内容。
来源字段用于治理，真正送入训练器前还需映射成其支持的数据列。

```json
{
  "sourceId": "ticket-demo-a",
  "annotationVersion": "report-v2",
  "messages": [
    {
      "role": "user",
      "content": "请根据练习记录生成工单进度报告。给定查询记录显示 T-1048 为 WAITING_VENDOR，观测时间为 2026-11-20 10:00（北京时间），没有新的供应商反馈。"
    },
    {
      "role": "assistant",
      "content": "给定查询记录显示，T-1048 截至 2026-11-20 10:00（北京时间）正在等待供应商反馈。尚无新反馈证据，后续进展需要重新查询，当前记录不能证明供应商已经处理。"
    }
  ]
}
```

真实训练样本需要人工核查事实、表述与授权要求，不能直接把任意线上回答当成正确答案。
敏感内容先脱敏，保留数据使用依据、来源、版本与允许用途，合成数据也要检查生成质量和重复程度。

含工具调用的样本还要保留正确的工具定义、参数、调用标识和对应结果。
被拒绝的越权请求可以作为行为样本，但工具权限依旧由服务端执行，不能交给模型记忆。

## 数据格式和 loss mask，为什么不能照抄另一模型的配置？

训练与推理要匹配 tokenizer、chat template、角色边界和结束标记。
不匹配时，模型可能学到错误的对话分隔，或者把输入提示也当成应生成的目标。

TRL 支持不同的数据格式，损失可以覆盖完整有效序列、completion 或受支持模板中的 assistant 部分。
实际行为取决于数据格式、配置和模板能力，必须抽样检查渲染文本、Token 和被计分的位置。
长样本截断还可能切掉答案、工具结果或关键约束，packing 的样本边界也要按具体实现核验。

验证配置时保留一条最小样本的可观察结果，不需要记录模型隐藏推理。
训练 loss 下降只能表明当前优化目标发生变化，不能证明业务表现已经改善。

## 怎样切分数据，避免把同一张工单的改写当成泛化？

同一工单的追问、改写、摘要和派生样本应归入同一来源组。
近重复材料还需要归并为同组，先分组再切分，不能按行打散后只检查完全相同文本。
分组标识可以来自来源关联与重复检测，再由人工核查边界。

下面演示“新用户、新工单、未来时间”这个评测目标，三种集合同时隔离来源组、近重复组和用户组。
已知用户的未来请求可采用另一种时间外推设计，应分别报告，不能混用两种结论。

```javascript
function checkSplit(rows) {
  const owner = new Map();
  const windows = {
    train: ["2026-01-01", "2026-01-31"],
    dev: ["2026-02-01", "2026-02-28"],
    test: ["2026-03-01", "2026-03-31"],
  };
  for (const row of rows) {
    const range = windows[row.split];
    if (!range || row.date < range[0] || row.date > range[1]) {
      throw new Error("样本越过约定的时间边界");
    }
    for (const field of ["source", "duplicateGroup", "userGroup"]) {
      if (!row[field]) throw new Error("缺少分组标识");
      const key = `${field}:${row[field]}`;
      if (owner.has(key) && owner.get(key) !== row.split) {
        throw new Error(`跨集合泄漏 ${key}`);
      }
      owner.set(key, row.split);
    }
  }
  return "分组和时间检查通过";
}

const rows = [
  { split: "train", date: "2026-01-10", source: "a", duplicateGroup: "n1", userGroup: "u1" },
  { split: "train", date: "2026-01-11", source: "a", duplicateGroup: "n1", userGroup: "u1" },
  { split: "dev", date: "2026-02-10", source: "b", duplicateGroup: "n2", userGroup: "u2" },
  { split: "test", date: "2026-03-10", source: "c", duplicateGroup: "n3", userGroup: "u3" },
];
console.log(checkSplit(rows));
```

代码可独立用 Node 执行，日期假定已标准化为有效的 `YYYY-MM-DD`。
把开发集样本的 `duplicateGroup` 改成 `n1` 会触发泄漏错误，改回训练时间也会被时间检查拒绝。
这个检查依赖分组标注，并未实现近重复识别，更不代表运行了模型训练。
最终测试集保持封存，开发集用于选配置，不能反复用最终测试结果调整样本或超参数。

## 训练完成后，怎样比较收益和退步？

在相同任务、可访问证据、工具权限和预算下，比较基座、改进提示词、RAG 与微调组合。
除目标格式外，还要检查事实依据、拒答、越权诱导、工具参数、领域外任务和已有通用能力。
模型输出有波动时进行多次运行，并报告样本量、分组结果、延迟和总成本。

业务硬约束单独判定，流畅度均分不能抵消一次未经授权的写入。
训练、模型选型和最终验收分别使用允许的数据，确认评测答案没有进入训练样本或检索语料。
更完整的执行环境与终态判据见[Agent 评测](./ai-agent-evaluation.html)。

## 发布时，怎样保证适配器能重现和回滚？

记录基座模型的准确修订、tokenizer、模板、适配器、目标模块、训练配置和数据版本。
验证部署使用了相匹配的基座与适配器，再灰度比较质量、资源和成本，保留已验证的回滚组合。

数据撤销还涉及训练样本、检查点、合并权重、发布副本和备份。
删除一个 adapter 文件不证明所有已发布模型都忘记了相关数据，处理方式需要有可追踪的保留与重训策略。

## 小结

1. SFT 是监督训练目标与流程，LoRA 是参数更新方法，可以组合，量化另有实现条件。
2. 样本保留合法来源与版本，训练前核查模板、Token、损失掩码和工具消息完整性。
3. 数据按评测目标分组与时间切分，近重复和派生内容不能跨集合污染结论。
4. 用独立任务比较质量、安全、通用回归和总成本，训练 loss 不能代替业务验收。
5. 发布绑定基座、适配器与数据版本，回滚和数据撤销要覆盖实际保存的副本。
